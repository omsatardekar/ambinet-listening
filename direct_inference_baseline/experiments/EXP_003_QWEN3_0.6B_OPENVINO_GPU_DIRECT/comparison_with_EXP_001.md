# EXP_003 vs EXP_001 - same five development encounters (00021, 00032, 00034, 00035, 00037)

Data source: `evaluation/comparison_with_EXP_001.json` (generated by `scripts/compare_with_exp001.py`, read-only on EXP_001).
Five encounters only: indicative, not statistically meaningful.

## What is the same and what is different
| Aspect | EXP_001 | EXP_003 |
|---|---|---|
| Model / source revision | Qwen/Qwen3-0.6B, c1899de2... | same |
| Numerical format | BF16 weights loaded as FP32 | weights converted BF16 -> FP16 (no quantisation); activations run in FP16 on the GPU |
| Runtime | Hugging Face Transformers 5.22.2 + PyTorch 2.15 CPU | OpenVINO GenAI 2026.4.1 `LLMPipeline`, fresh pipeline per encounter |
| Hardware | i7-8665U CPU | Intel UHD 620 iGPU (same laptop) |
| Prompt | sha256 78c5ab95...f604 | identical (verified) |
| Chat template / thinking | Qwen3 template, enable_thinking=False | same template applied via OpenVINO tokenizer, enable_thinking=False |
| Decoding | greedy, max_new_tokens 6144 | greedy, max_new_tokens 6144 |
| Dataset, split, ids | frozen corrected dataset, dev split | identical (verified); input token counts equal for all five |
| Evaluator, parser, schema validator | existing code | byte-identical code (verified against EXP_001 snapshot) |

## Extraction and schema results (strict, end-to-end)
Entity-matching results are **identical**: micro P/R/F1 0.111 / 0.018 / 0.030 (TP 3, FP 24, FN 168), macro F1 0.019; every per-category count, every attribute
count, negation, vital-sign and speaker metric, and the specialty/complexity breakdowns are unchanged. JSON validity 5/5 and schema compliance 0/5 in both.

Differences found (all small):
* Evidence grounding (27 predicted entities in EXP_001, 27 in EXP_003): strict 2 -> 0, partially supported 4 -> 2, unsupported 21 -> 25 (77.8% -> 92.6%).
* Required-field completeness 94.36% -> 94.42%; enum violations 9 -> 10.

## Interpretation limits
* The 3.7x lower latency is a combined effect of runtime (OpenVINO vs PyTorch), numerical format (FP16 vs FP32) and hardware (iGPU vs CPU). This experiment
  cannot attribute it to the GPU alone; the EXP_002 measurements suggest OpenVINO on the CPU is already much faster than PyTorch FP32.
* The extraction metrics were unchanged within this sample, so moving to OpenVINO FP16 on the iGPU did not visibly harm extraction quality on these five encounters;
  it also did not improve it. The poor quality (very low recall, 0/5 schema compliance) is a property of the model/prompt combination, not of the backend.
* Differences in evidence-grounding figures rest on 27 predictions from 5 encounters and should not be over-read.
