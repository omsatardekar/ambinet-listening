# Batch 002 (500 new synthetic encounters)

Status: generated and automatically validated on 2026-11-13. **Not clinician reviewed. Not allocated** to training, development or evaluation (that decision is separate and still open).
Batch 001 (`../output`, `../scenario_blueprints`, ...) is frozen and untouched; Batch 002 lives only in this folder and reuses the parent `../schema/final_label_schema.json` (not copied).

## Purpose
A second, clinically different set of 500 paired transcripts and ground-truth labels in the same schema, built to contain the extraction challenges found in the P05 root-cause investigation
(medicine identity and dose placement, allergy status, negation, speaker attribution, temporality, cases where the right behaviour is to abstain). It is a data resource; no model was run on it.

## Method (short)
Reuses the unmodified Batch 001 pipeline (blueprint -> dialogue -> label from the same turns -> validator). New in this folder: 60 clinical profiles (5 per specialty), look-alike drug options, new surgical/family/allergy/social wording, replacement wording for routine question/answer pools,
a new plan (12 specialties x tiers Simple 150 / Medium 225 / Hard 125, i.e. generator complexity simple / moderate / complex 75 + challenging 50), seed 20261114, ids 20001-20500, and extra acceptance gates (latent-age plausibility, planned-vs-conditional wording, duplicate generic medicine, clinical-identity uniqueness).
Failed attempts are regenerated from the same slot and logged; nothing is silently dropped.

## Composition (measured)
Specialties: General medicine/primary care 50, Cardiology 45, Respiratory 45, Gastroenterology 45, Endocrinology/diabetes 45, Neurology 45, Orthopaedics 40, Dermatology 40, Women's health 40, ENT/Ophthalmology 30, Infectious diseases 40, Urgent care/other 35.
Tiers: Simple 150, Medium 225, Hard 125 (see `reports/DISTRIBUTION_REPORT.md` for the per-specialty table and the measured coverage of each requested challenge).

## Validation (automated only)
500/500 pass the Batch 001 validator; existing final schema audit PASS (0 failures in ~392,000 check evaluations); 22/22 negative controls caught; lexical evidence grounding complete; independent label/transcript/blueprint checks all pass (numerators and denominators in `reports/VALIDATION_REPORT.md`); 0 exact or near duplicates.

## Known limitations
* Clinical content is hand-authored from general knowledge and not clinically reviewed; plausibility exclusions are simple.
* Conversation structure comes from the unmodified Batch 001 dialogue engine: question wording is new, but template scaffolding remains (about 57% of long segments also occur in another Batch 002 encounter; 10.9% occur verbatim in the 100 Batch 001 development transcripts; similarity to the 400 locked-test records was not measured because they may not be opened).
* Profile diversity is lower than Batch 001 (60 profiles, each used 6-10 times; Batch 001: 108 profiles, up to 6 uses). Look-alike drug names co-occur in only a small share of encounters (see the distribution report).
* Labels are generator-derived and consistency-checked, not independently human annotated. Confidence fields are null.
* No acoustic or recognition errors, overlapping speech or real-world irregularity.
* Reproduction note: the validator derives its symptom-category table from registered profiles, so the Batch 002 profiles must be registered before validating; the wrappers do this.

## Reproduce
From `dataset_v2_batch_001_corrected/batch_002/scripts` (Python 3, no packages; use `-B` to avoid writing bytecode into the frozen folders):
```
python -B generate_batch_002.py                    # refuses to run if output/inputs is not empty; regenerates all 500 deterministically (seed 20261114)
python -B b2_independent_checks.py                 # independent checks + Batch 001 validator on Batch 002
python -B b2_novelty_vs_batch_001_dev.py           # novelty vs the 100 Batch 001 DEVELOPMENT records only
python -B run_existing_tools_on_batch_002.py       # unmodified Batch 001 final audit, negative controls, checksum list, validator driver
(cd .. && python -B ../scripts/audit_metrics.py . reports/metrics_batch_002.json)   # run from batch_002/: same metrics script as Batch 001
python -B b2_make_reports.py                       # distribution, manifest and reports
python -B verify_batch_001_unchanged.py            # Batch 001 files still match the frozen FINAL_MANIFEST.json
```
Long-term plan: 8 batches x 500 = 4,000 encounters. Only Batch 002 exists beyond Batch 001; no later batch has been generated and no training/evaluation allocation has been made.
